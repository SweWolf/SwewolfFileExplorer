# SweWolf File Explorer (SwewolfFileExplorer)

A Windows File Explorer clone built with C# (.NET 10) and WPF.

## Build & Run

```bash
dotnet build
dotnet run
```

The user tests the **Release** build: after every change run `dotnet build -c Release -p:Platform=x64` (output `bin\x64\Release\net10.0-windows\SwewolfFileExplorer.exe`), so they can run it without Visual Studio.

## Architecture

- Pattern: **MVVM**. `MainWindow.xaml.cs` handles UI events only (double-click, F2, context menu clicks) and delegates all logic to `MainViewModel`.
- NuGet packages: **TagLibSharp 2.3.0** (tags of music files; same version as FileInfoViewer), nothing else so far. Packages are **not forbidden:** the user said (2026-10-15) that if a package would help, ask him at that moment; he will probably say yes. Say so in advance when a feature would need one (e.g. MetadataExtractor for image EXIF, as the sibling FileInfoViewer uses).
- Target platform: **Windows x64** (`net10.0-windows`).

## Key Design Decisions

- **Async icon loading**: `FileItemViewModel.LoadIconAsync()` fetches shell icons on a background thread and marshals back to the UI dispatcher. This keeps the list responsive when navigating large folders.
- **Lazy tree loading**: `TreeItemViewModel` adds a dummy child on init so the expand arrow appears. On first expand, `LoadChildren()` replaces the dummy with real subdirectories.
- **Clipboard**: Cut / Copy / Paste use the **Windows clipboard** (`Helpers/FileClipboard`: a file drop list plus "Preferred DropEffect", Copy = 1, Move = 2, as Explorer does), so files go to and come from Explorer and other instances. Copy of something inside an archive unpacks it first to the temp folder (`RealPathOf` / `ExtractToTemp`; gone when the app ends). Paste is enabled when the clipboard holds files (`FileClipboard.HasFiles`). After a cut-paste the clipboard is cleared, as Explorer does; moving a folder to another drive copies, then deletes (`MoveDirectory`). Cut items are not faded in the list (not done).
- **Column layout**: right-click a column header for a checklist of columns and "More..." (Choose Details dialog: order, show/hide, width). Hidden columns are kept in `MainWindow`'s `_layout` list and removed from the GridView. The layout is saved on every change and on close in `%AppData%\SweWolfSoftware\SweWolf File Explorer\columns.json` (`ColumnLayoutStore`).
- **Tree follows the folder**: every navigation (list, address bar, back/up) expands the tab's tree to the folder and selects its node (`SelectInTree`). A node selected this way is remembered in `_programmaticSelection`, so the window does not treat it as a click and navigate again.
- **Folders in the list**: hidden by default (they are in the tree); the "Folders" toggle button in the toolbar shows them. `SharedState.ShowFolders`, saved in `settings.json` (`AppSettingsStore`) next to `columns.json`. `FolderTabViewModel.Refresh()` also re-reads the current folder's tree node, so new, renamed or deleted folders show in the tree.
- **Font size**: Ctrl + mouse wheel over the list or over the tree changes that control's font size (8-40 pt, default 13), separately. The new size is flashed in the title bar for 2.5 s and saved in `settings.json` (`ListFontSize`, `TreeFontSize`). Always save through the one settings object, `AppSettingsStore.Current` (`SharedState.Settings` is the same instance), so one setting never overwrites another.
- **Name**: the app is called "SweWolf File Explorer" in the UI (`AppInfo.Name`, main window title); "My File Explorer" was a beta name. The settings folder is `%AppData%\SweWolfSoftware\SweWolf File Explorer` (`AppInfo.Name`; settings of the beta name were not moved). The EXE, project, namespace and repository are `SwewolfFileExplorer` (renamed from MyFileExplorer before any release).
- **About**: **Help > About** (`Views/AboutWindow`, as in the siblings: blue banner with icon, version from the assembly and "latest version" check against GitHub Releases `SweWolf/SwewolfFileExplorer`, silent when offline or when there is no release yet). The version is `<Version>` in the .csproj. Help has no "SweWolf File Explorer Help" item yet (no help file).
- **Menu, Settings, Create Shortcut**: the menu bar has **Tools > Create Shortcut...** (desktop / Start menu, current or all users; `Views/CreateShortcutWindow`, as in the sibling apps, but without "Send To" until the app accepts a folder on the command line) and **Tools > Settings** (`Views/SettingsWindow`: Appearance > Style: Light / Dark / System, default System, saved as `Style` in `settings.json`). Message boxes of these windows use `AppInfo.Name` as caption (older ones still say "Error").
- **Cyber style** (working name; the user will rename it): the Dark theme with black backgrounds and light blue text (#ADD8E6, the colors of the old TeraTool). `ThemeService.ApplyCyberColors` replaces the theme's own white-text and window-background brushes by name in `Application.Resources` and removes them again when another style is chosen.
- **Hidden items**: files and folders with the Hidden or System attribute are not listed. A line under the list says "N hidden items (click to show)" and toggles them for the current folder (`FolderTabViewModel._showHidden`, reset on every navigation, kept on refresh); shown ones are faded (`FileItemViewModel.IsHidden`). **Inside compressed files** a second list applies on top of the first (`AppSettings.HiddenExtensionsInArchives`, Settings > Hidden Files > "Also Hide Files with These Extensions When Inside Compressed Files", empty by default; `HiddenItems.IsHiddenInArchive`, used by the list, the read-state and the next-folder search): e.g. the nfo / txt files that come with a comic.
- **Archives (.zip, .cbz read by .NET; .rar, .cbr, .7z read by 7-Zip)** (`Helpers/ArchiveSupport`; `ArchiveReader` has one implementation per way of reading: `ZipReader` and `SevenZipReader`; `Helpers/SevenZipRunner` runs `7z.exe`: `l -slt -ba` lists, `e -so -spd` writes one file to the output, so RAR/7z are read in place too, like zip; 7-Zip is found through the registry (`HKLM`/`HKCU` `SOFTWARE\7-Zip`), Program Files, then the PATH; without it entering a RAR shows "7-Zip is needed ..." in the status bar; every call passes a dummy `-p` password, so an archive that needs a password fails at once with a clear message instead of 7-Zip waiting for input; an archive inside another one: a zip is read into memory, anything else is unpacked once to `%TEMP%\SwewolfFileExplorer\<pid>\nested\`; any mix works: zip in RAR, RAR in zip ...; a RAR that stores no date shows the date of the archive file; a **solid** RAR is slow for one picture after another, as 7-Zip must decode what comes before it). A packed file is a folder. In the tree the archives come after all the folders, with their extension (`TreeItemViewModel.IsArchive`; always an expand arrow, as looking inside costs a read); Enter / double-click on one in the list enters it; the address bar takes `D:\Photos\Trip.zip\Day 1`, and a zip inside a zip works (`...\All.zip\Trip.zip\Day 1`). They are read **in place** (`System.IO.Compression`, nothing is unpacked to browse); an index per archive is cached (`GetIndex`, invalidated by F5 / `Refresh`). Every path in the app can be such a path: `FileItemViewModel.IsInArchive` makes the icon and type come from the name (`IconHelper.GetIconForName`, cached per extension); `ArchiveSupport.OpenAnyFile` is what `PictureLoader` / `ThumbnailLoader` read through, so the viewer and the thumbnail work on pictures inside archives. A file opened from an archive is unpacked to `%TEMP%\SwewolfFileExplorer\<pid>\<guid>\` first (`FolderTabViewModel.RealPathOf`; removed at exit, stale ones at start). **Read-only:** inside an archive Cut, Delete, Rename, New Folder, Paste, Send to and Properties are disabled (`FolderTabViewModel.InArchive`); Copy then Paste into a real folder unpacks (files, folders, a zip inside a zip as the file). **Sort inside an archive:** by default none (`SortColumn.None`, the view has no `CustomSort`): the files show in the order they are stored in the zip, with no arrow in a header, as in TeraTool; a click on a header sorts (and is remembered for that folder like any folder's sort). Real folders still default to Name. The same for the tree: the folders (then the zips) inside an archive show in stored order until a sort is chosen in the tree's Sort By box, which is then empty (`SharedState.GetTreeSort` gives `None`, `TreeSortIndex` -1); choosing a column or a direction there sorts them. There is no way back to "stored order" except opening the archive again in a new run (the choice is not saved yet). Names without the UTF-8 flag (older tools, Windows' own "Send to compressed folder") are read in the computer's DOS code page (`NameEncoding`), as Explorer does: .NET would read them as UTF-8 and show "�" for å, ä, ö. Dates are the DOS time stored in the zip (the wall clock of the computer that zipped it); Explorer may differ by hours because it uses the UTC timestamp some zips also carry. The path of a zip inside a zip is both the file and the top of its archive: `Locate(..., asEntry)` picks. Not done yet: tar / gz / bz2 / xz and the other formats 7-Zip knows (only `ArchiveSupport`'s extension lists and `FilePatterns` need them), passwords (a message says it is protected; asking for the password is a later step), multi-volume RAR (`.part1.rar`), a setting for where 7-Zip is, a progress bar for very big archives (the tree reads the archive on the UI thread when expanded).
- **Picture viewer** (`Views/PictureViewerWindow`, modeled on TeraTool's `frmPicture`; spec and source are read-only references): Enter, double-click and Open on a picture (`ThumbnailLoader.IsImage`) open it here instead of in the program Windows has for it; **Open With...** in the context menu opens the Windows "Open with" dialog. The viewer starts full screen on black (covers the taskbar; `WindowStyle.None` + `NoResize` + `Maximized`), F11 / F / double-click toggle a window with a title bar that is still maximized (the taskbar shows again). It goes through the pictures of the list as sorted (`PictureChanged` makes the list select the current one; after Delete the list is refreshed). Keys: Left/Right, PageUp/PageDown, Backspace/Space/Enter/N/P, Home/End, wheel (down = next), click (left third = previous, else next, delayed by the double-click time so a double click is not also a click); Esc/X closes; numpad +/- or Ctrl + wheel zoom (about the mouse), numpad * = Stretch (fit, may enlarge), numpad / = Normal Size (fit, never enlarges); drag pans when zoomed; Ctrl+K / Ctrl+L rotate **for viewing only: the viewer never writes a file** (decision of the user, to be revisited); Delete asks, then moves the file to the Recycle Bin. `PictureLoader` reads the file into memory (never locked), applies EXIF orientation, and animates GIFs (`GifAnimator`). The picture lives in a `Canvas` and is placed only by its `RenderTransform` (`UpdateTransform`): in a Grid a picture bigger than the window is squeezed to the window's size and then scaled again (a 6016x4000 photo showed small and distorted). Blocks the screensaver and screen sleep while open. Pictures inside an archive work (Delete says it cannot delete from an archive). **End of the list (built 2026-10-17, modeled on TeraTool's choice box):** going back past the first picture only flashes "This is the first item in the list" and stays (no wrap any more); going forward past the last opens a `ChoiceDialog` (also for a list of one picture): **Go to Next Folder** / **Start from Beginning** / **Close** (Esc). The message shows the **full path of the next folder**, or "There is no next folder." with the first button greyed out. `Helpers/NextFolderFinder` finds it in **tree order** (into the subfolders first, then the next sibling, then the parent's next sibling ...; the tree's sort order per folder, packed files after the folders and entered like folders, so zip to the next zip works; hidden folders only if the tree shows them; junctions skipped), **never leaves the drive**, and only stops at a folder or packed file with a **visible picture** directly in it (hidden attribute or hidden extension do not count; videos do not count yet). It is path based and runs on a background thread, **started as soon as the last picture is shown** (`StartNextFolderSearch`, one per folder, canceled on close), so the dialog opens with the answer ready; if it is still running the dialog says "Looking for the next folder..." and fills in when done. The viewer gets two callbacks from `MainWindow.OpenInViewer`: `FindNextFolder` and `OpenFolder` (navigates the active tab there, so list, tree and address bar follow, and returns the pictures of the list). **Countdown:** the first button is pressed by itself after 10 s, its text shows `[n]`; any mouse movement (more than 2 px), mouse click or key press stops it and the number goes away (`ChoiceDialog.CountdownSeconds`; it starts when the default button becomes enabled). `Views/ChoiceDialog` is generic (`ChoiceDialog.Ask(owner, message, buttons, defaultIndex, cancelIndex, countdownSeconds)` or `new` + `SetMessage` / `SetButtonEnabled` while open). Tested: the finder on a throwaway tree with two zips (skips empty, hidden-only and no-picture folders, goes zip to zip), the countdown (auto-press after 3 s, stopped by input). **Not tested end to end** in the real viewer (Navigate from inside the modal viewer, tree selection). Not done yet (on purpose): slideshow (the countdown is made for it), videos in the next-folder test, starting the app with a file path.
- **Info panel under the list**: "File 14/17" (place of the selected item in the list as sorted, computed in `MainWindow.UpdateInfoPanel`) and a thumbnail of the selected picture. `ThumbnailLoader` reads the file with `FileShare.ReadWrite | Delete`, decodes it into memory (`OnLoad`) and closes it, on a background thread, so the preview never locks the file. (The thumbnail does not apply EXIF rotation yet; the viewer does.)
- **Dark mode**: `ThemeService.Apply` sets `Application.ThemeMode` (Fluent Light or Dark; experimental API, WPF0001 is silenced in the .csproj) and the app's own brushes (`PaneBrush`, `LineBrush`, `TabHoverBrush`, `TabSelectedBrush`, `SplitterBrush`), which the XAML uses with `DynamicResource`: never hard-code a color in XAML. Applied before the main window opens (`App.OnStartup`) and again on a change in Settings; "System" follows Windows live. Switching back to the classic theme (`ThemeMode.None`) at runtime leaves wrong colors, so don't use it. **The default button of a dialog** (`IsDefault`) is marked with a 2 px accent outline set **on the button itself** (`BorderBrush="{DynamicResource {x:Static SystemColors.AccentColorBrushKey}}" BorderThickness="2"`; in `ChoiceDialog` in code): the Fluent theme only shows the default while the button has focus, and in most dialogs the focus is in a text box. **Do not do it with an app-wide `Style TargetType="Button"`**: an app-level style replaces the theme's own button style (tried: every button went classic gray). Fluent makes the list rows 40 px high (42 px apart); the list has its own `ListView.ItemContainerStyle` (MinHeight 26, Padding 4,1: 28 px apart) that **must be based on `GridView.GridViewItemContainerStyleKey`** (based on `{x:Type ListViewItem}` it loses the GridViewRowPresenter and every row shows `...FileItemViewModel`; found by screenshotting a scratch build). The Choose Details list does the same for its `ListBoxItem`s and its `CheckBox` has `MinHeight="0"` (the Fluent checkbox is 32 px high); that dialog is resizable (`CanResizeWithGrip`, the list takes the extra height). **How to look at the UI without touching the user's running app:** `dotnet build SwewolfFileExplorer.csproj -c Release -p:Platform=x64 -o <scratch>	estout`, then start that copy with `Start-Process -PassThru` and capture its window by handle (`CopyFromScreen` of `GetWindowRect`, DPI aware) and Read the PNG; for a dialog, a tiny throwaway WPF app that references the DLL, shows the dialog and renders it with `RenderTargetBitmap`.
- **Tree header**: above the tree: an up button (`UpCommand`), "Sort By" (Name / Date Created / Date Modified, Asc / Desc) and an "x" (flat, red under the mouse like a Windows close button: `CloseHoverBrush`, `ClosePressedBrush`) that hides the tree pane (F8 or the "Tree" toggle in the toolbar shows it again; `MainViewModel.ShowTree`, `MainWindow.UpdateTreePane`, not saved). The sort is per folder and sorts that folder's subfolders: `SharedState.TreeSorts` (in memory only, like `FolderSorts`: to be saved later in the DB file). `TreeItemViewModel` gets the lookup (`TreeSortLookup`) and `Resort()` moves the loaded nodes in place. Modeled on TeraTool (spec: `G:\My Drive\TeraTool_spec\`, source: `G:\My Drive\TT-SourceCode`, read-only).
- **Root of the tree (built 2026-10-17):** a tab can have a folder, a packed file or a folder inside one as the **top of its tree** (`FolderTabViewModel.RootPath` / `HasTreeRoot` / `SetTreeRoot` / `ResetTreeRoot`; `RebuildTree` swaps the tree for the root's one node, expanded, or back to Quick Access + This PC). Set it with **right-click on the "Go" arrow** next to the address bar (**Set as Tree Root** uses the text in the address bar; **Reset Tree Root**) or in the **tree's right-click menu** (same two items, for the folder under the mouse). **Not remembered**: a new tab always has the normal tree (user's decision). Rules (the user's answers): going to a path **outside** the root (address bar, Back/Forward, a link) resets the tree to normal and opens the folder (`Navigate` calls `ClearTreeRoot`); **Up and Backspace stop at the root** (`CanGoUp`); the **next-folder search in the picture viewer never goes above the root** (`NextFolderFinder.Find(..., root)`: no next folder there). `ResolveNode` / `WalkDown` find the node from the root's node, so selecting the current folder in the tree works inside archives too. A bad path says "The folder ... does not exist." Tested headless with a throwaway app (root set / reset, Up stops, outside path resets, zip and folder-in-zip as root, bad path) and the finder with and without a root; the user then tried it in the real window (menus, tree redraw): works.
- **Workspaces and sessions (built 2026-10-17, names and rules decided with the user):** two main menus, **Workspace** and **Session** (before Tools). A **workspace** = folders the user saved by hand (`Save Current Tabs as Workspace...`): opening it opens each folder in its own tab. A **session** = the open tabs remembered **all the time** (`Start New Session...`, name it; the window title then says `- Session <name>`; `Stop Session` stops recording, the file stays). Both menus have Open (a list of the saved ones; the session in use has a check mark), Open from File..., Delete, Show Folder; Workspace also Save, Session also Start/Stop. **Files:** one **JSON file per workspace or session, named exactly as the user named it**, in `%AppData%\SweWolfSoftware\SweWolf File Explorer\Workspaces\` and `...\Sessions\` (easy to copy to another computer; the name is the file name, there is no name inside). The file says what it is with `"Format": "SweWolfFileExplorer.Workspace"` or `"...Session"` (so the program knows it wherever it lies); `Tabs` = `Path`, `Root` (the tab's tree root), `SelectedFile` (sessions only); `ActiveTab`. **No back / forward history** is saved. `Helpers/WorkspaceStore` (read, write the safe way: temp file then swap, names, `CheckName`), `ViewModels/SessionRecorder`, `FolderTabViewModel.CaptureState / Restore`, `MainViewModel.CaptureState / RestoreTabs`. **Autosave:** half a second after a tab is opened or closed, a folder shown (`Title` changes: not while typing in the address bar; `FolderPath` is the last successful navigation), a root set or reset, or another tab made active; the **selected file only after it stayed selected 3 s** (no write per file while holding an arrow key); written on a background thread, one at a time, an old state never overwrites a newer one; written at once on close. **Never a session with no tabs** (the last tab closing ends the program: the session stays as it was just before). **Opening:** the program never opens one by itself; if the user has been clicking around (`HasUserActivity`: more than one tab, or a tab that was navigated or has a root) a question. **Workspace:** "Do you want to close all current tabs first?" Yes / No / Cancel (Yes = replace, No = add the new tabs). **Session** (user's correction: a session is never mixed with open tabs): "All open tabs will be closed. Continue?" OK / Cancel, always replaces. Right after the start there is no question (the start tab is replaced). **Menu order:** Tools, Workspace, Session, Help (Tools first, user's choice). The two **"Open ... from File..." items are hidden** (`Visibility="Collapsed"` in `MainWindow.xaml`; handlers and `OpenTabSetFromDialog` kept: a possible future feature, the user found them clutter): a file is still opened through the command line. **A file on the command line** (`SwewolfFileExplorer.exe "C:\...\A.json"`; `App.StartupFile`, opened by `MainWindow` on Loaded) is opened as what its `Format` says; a session goes on being saved into **that** file, wherever it is. **A folder that is not there** (a USB drive not connected) is **never removed**: its tab shows "<name> (unavailable)" and the note "Currently unavailable: <path>. The drive may not be connected. Press F5 to try again." (also kept when the list clears its selection); the path, root and file stay in the saved state; Go or F5 tries again, and a saved root is applied then (`_pendingRoot`). The selected file of a restored tab is selected when the tab first becomes the active one (`RaisePendingSelection`). Tested headless (26 checks: files, restore, unavailable and its return, root, selected file, session file) and in a scratch copy started with a session file (3 tabs, one unavailable: title, tab strip, selected file, autosave of the active tab). Not done: managing (rename) inside the program (rename the file in the folder), a "last session" that opens by itself (user said never).
- **Hidden folders in the tree**: the tree does not list folders (or packed files) with the Hidden or System attribute (`$RECYCLE.BIN`, `System Volume Information`, ...). A line under the tree says "N hidden folders (click to show)" about the **current folder's** subfolders (`FolderTabViewModel.HasTreeHiddenFolders` / `TreeHiddenText` / `ToggleTreeHiddenCommand`, counted in `LoadItems` by `TreeItemViewModel.CountHiddenIn`). Unlike the list, the choice is **kept** per folder, in `SharedState.TreeShownHidden` (this run only; shared by all tabs, which sync through `TreeHiddenChanged`), because resetting it on every navigation would take away the node of the hidden folder you are in. Shown ones are faded (`TreeItemViewModel.IsHidden`). `TreeItemViewModel.SyncChildren()` adds or removes the nodes in place (expanded nodes and the selection stay). Opening a hidden folder from the list or the address bar turns the setting on for its parent (`ResolveNode`). A folder whose only subfolders are hidden has no expand arrow until they are shown.
- **Folder picture** (under the tree, `Helpers/FolderCoverFinder`, `FolderTabViewModel.UpdateFolderPicture`; modeled on TeraTool's `ShowFolderPicture` / `GetCoverPictureFromZipFile`, which only looked for `Folder.jpg` in a folder and a cover-like picture in a zip): shown at the very bottom of the tree pane (below the hidden-folders line) for the **current folder**, 500 px decoded, at most 220 px high; the area (233 px) is **always there**, empty when the folder has none (most folders), so the tree does not jump; no tooltip. Looked up in the background on every navigation / F5 (the old picture goes at once). Order: (1) a picture in the folder named Folder, Cover, Front, Poster, AlbumArt* (WMP's `AlbumArt_{GUID}_Large`), Album, Thumb, Thumbnail, or like the folder, or ending in `cover` (hidden files count: `Folder.jpg` usually is hidden); among equals the biggest file; (2) the cover embedded in the first 5 music files (`AudioTagReader.ReadCover`, front cover first); (3) in an archive: the same names, stepping into a single folder inside it (up to 3 levels; comics keep their pages in one), and for `.cbz` / `.cbr` page 1. **No** "first picture of the folder" fallback on purpose (random in a photo folder). A single click opens it in the picture viewer (an embedded cover is saved to the temp folder first). Tested on 108 of the user's folders: 60 named picture, 3 embedded, 45 none; 18 of 31 archives (all comics; ordinary zips correctly none). A RAR costs a 7z.exe run (0.1-1.7 s, in the background). **Not done:** a cover the user chooses (or clears) for a folder (TeraTool kept it per folder; it belongs in the per-folder database), cycling through candidates, downloading covers, a cover for a zip/RAR *file* shown in a list.
- **Columns of the list** (right-click a header; `_layout`): Name, Date Modified, Date Created, Type, Size, and the **tags of music files** Artist, Title and Track Number (as in TeraTool; hidden by default). The tags are read by **TagLibSharp** (`Helpers/AudioTagReader`: tags only, `ReadStyle.None`; mp3, m4a, flac, ogg, opus, wma, wav ...). It replaced the Windows property system after a test on 153 of the user's files (2026-10-15): same files had tags with both, but Windows gave no artist for FLAC/WMA files that only have an Album Artist, and TagLibSharp was ~6x faster (62 ms for all 153 on several threads). The artist is the performers, else the album artists. They are read in the background, 4 at a time (`FolderTabViewModel.EnsureTags`), **only** while a tag column is shown or sorted by (`SharedState.TagColumnsVisible`), and each cell fills in when its file is done; a sort by a tag column is redone when all are read (`TagsLoaded`). **Not done:** tags of files inside archives (TagLibSharp can read a stream; for a RAR every file would cost a 7z.exe run, so it needs thought); TeraTool's Position, Info (read status), Rating, Expectation (they need the per-file database, see the idea list) and URL (link lists); more columns (Album, Genre, Year, Duration, image size ...) can come from TagLibSharp or, for images and video, from the Windows property system as FileInfoViewer does (`Services/ShellPropertyReader.cs` there).
- **Right-click menu of the tree** (`TreeContextMenu`, `MainWindow.TreeCtx*`): works on the folder under the mouse, which need not be the current one (`_treeMenuNode`; no menu on Quick Access / This PC). A folder or archive is derived: **unread** (nothing under it opened), **partly read** (starts when the first file in it is opened) and **fully read** (every file in it **and in all its subfolders** opened). ## Extending the App

- **New toolbar action**: add a `RelayCommand` property in `MainViewModel`, wire up `CanExecute` logic, then add a `<Button>` in `MainWindow.xaml` bound to the command.
- **New context menu item**: add a `<MenuItem>` in `MainWindow.xaml` with a `Click` handler, then call the relevant `MainViewModel` method from `MainWindow.xaml.cs`.
- **New converter**: add a class implementing `IValueConverter` in `Converters/`, register it as a resource in `MainWindow.xaml`, and use it in a `DisplayMemberBinding` or `CellTemplate`.
